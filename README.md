goboxd is a containerised HTTP service written in Go that compiles and executes untrusted code inside isolated `nsjail` namespaces, returning exact timing, standard output, standard error, and exit status results per test case.

---

## 🚀 Key Features

- **Plug and Play Language Registry:** Driven entirely by standard YAML configurations under `configs/languages.yaml`. Adding a language requires no changes to the Go codebase.
- **Process Isolation:** Runs code using Linux namespaces, cgroups, and resource limits under Google's secure `nsjail` runtime.
- **Bounded Concurrency:** Protects the host system against denial-of-service attempts using an internal semaphore queue matching CPU cores.
- **Automated Orchestration Probes:** Contains separate lightweight `/healthz` and deep-probing `/readyz` endpoints checking nsjail and every compiler toolchain.
- **Microservice Design:** Built with `github.com/go-chi/chi/v5` for lightweight, zero-allocation routing, and `go.uber.org/zap` for high-performance structured JSON logging.

## 🔒 Security Holes Closed

We have systematically audited the system and implemented bulletproof defenses against common security exploits:

1. **Path Traversal via Filename:** The `source_filename` and `artifact_filename` inputs are validated by `validator.ValidateFilename` to ensure they contain exactly one standard path component with absolutely no path separators (`/`, `\`), directory traversals (`..`), or hidden files (leading `.`).
2. **Shell Command Injection:** All filesystem directory lifecycles (creation, staging, and removal) are executed via native Go API bindings (`os.MkdirAll`, `os.RemoveAll`) and clean platform-agnostic paths (`filepath.Join`), entirely bypassing shells.
3. **Compiler Flag Injection:** The system checks all user-supplied compilation flags against a strict allowed list defined per-language in the YAML configuration (e.g. `flag_allowlist`). Any unsupported flags trigger an immediate `HTTP 400 Bad Request`.
4. **Denial of Service (DoS) via Payload Size:** Hard payload limits are enforced at the network boundary: the total HTTP request body is capped at **1 MiB**, source code size at **256 KiB**, standard input strings at **64 KiB**, and total batch test cases at **50**.
5. **Jail Directory UID/Name Collisions:** Isolated environments stage files inside temporary paths generated by `os.MkdirTemp`, guaranteeing complete global uniqueness on the host filesystem.
6. **Unbounded Output Memory Exhaustion:** Output read streams are wrapped in `io.LimitReader` capping standard output and standard error at **64 KiB** each. If user programs print past this limit, the system gracefully truncates it and appends a `\n[output truncated]` marker.
7. **Stale Jail Directories Cleanup:** Sandboxes automatically register safe garbage collection via deferred `Cleanup()` methods (guaranteed to execute even on panic). Furthermore, an active startup sweeper scans `/var/jails` to remove orphan directories older than 10 minutes from crashed/killed processes.

## 🛠️ Usage and Commands

All components are fully containerised. No local Go toolchains, compilers, or interpreters are required on your host system—everything builds and runs seamlessly within the Docker runtime.

### Prerequisites
- Docker and Docker Compose v2

### Commands
```sh
make build        # Build the goboxd runtime and tools images
make run          # Start the goboxd API service on localhost:8080
make test         # Execute all unit tests in a clean tools container
make integration  # Spin up the background API service and run automated E2E tests
make lint         # Run static analysis and style audits using golangci-lint
```

```

```
